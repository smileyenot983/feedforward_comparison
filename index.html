Metric definitions & aggregation
Object / background disagreement
Relative cross-view depth disagreement in foreground / background, including occluded points. This is consistency between predictions; views can agree even when the reconstructed shape is wrong.
Object depth error
Relative difference |prediction − reference| / reference on valid foreground CO3D depth pixels. These COLMAP reference depths can contain errors.
Scoring pixels
The shared-pixel group uses a common 512 evaluation grid and the intersection of the five primary model masks. The other groups use the separate masks or grids described in their headings.
Model input / cameras used
Model input lists what entered inference. Cameras used lists the cameras that place the predicted points in the scene. Known or provided cameras come from CO3D; predicted cameras come from the model.
Aggregation
Scene-balanced median of per-scene medians. Reference error uses frame medians within each scene. Scenes without a valid score are omitted; object / background scene counts are shown for each row.
Runtime / memory
Saved inference runtime and peak allocated GPU memory. Grids and execution paths differ; these measurements are indicative. GGPT runtime includes Pi3X, matching, camera optimization and refinement.
Missing values
“—” means unavailable or not applicable. The sparse CO3D baseline has no self-comparison error or inference timing.

Methods & evaluation setup

This page presents an exploratory comparison on 20 selected CO3D scenes, using 10 views per scene. It is a saved experiment, not an official benchmark or an evaluation of the full dataset.

Known and predicted cameras

Known cameras provide each image’s camera position, orientation and calibration from CO3D. Camera-conditioned Pi3X, DA3, MapAnything and pairwise Pow3R runs received these along with the images. Images-only variants estimate their cameras. VGGT-Omega received images alone: one cloud uses known cameras to place the predicted depths, while the other uses predicted cameras.

Pointcloud display

Clouds combine points from the selected views without surface fusion or smoothing. All methods share one scene display transform, scale and viewpoint. Object-only display hides background points. Each method retains its saved geometry-validity mask.

Sampling & evaluation details

Clouds were sampled at stride 3 and capped at 60,000 foreground and 20,000 background points per method. These display samples are separate from the evaluation pixels. Use Fit scene in the viewer to inspect distant points.

RGB-only MapAnything and Pi3X predict their own cameras; CO3D cameras are used afterward for a single similarity alignment and evaluation. GGPT refines Pi3X with matching and camera optimization, retaining corrected XYZ. Its camera-conditioned, RGB-only and fast-matcher variants have separate retained-pixel intersections.

This public export preserves the original experiment’s pointclouds and scores. It does not substitute later 30-view preprocessing or filtering results.
